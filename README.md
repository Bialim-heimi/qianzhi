# 签纸 · 一念一签

## 网页预览

刷新 dist/index.html 即可查看新版。无需安装依赖。
网页默认没有铰链硬件连接，因此不会自行合纸或展签。
如需在桌面验证流程，展开 APP 画面之外的“桌面调试 · 模拟设备姿态”：
1. 在纸上写下问题。
2. 将调试滑杆从 180° 拖至 0°，模拟设备完全合拢。
3. 点击“轻摇一次”三次。
4. 将滑杆拖回 180°，模拟设备完全展开；签文自动呈现。
5. 点击“细读签意”进入独立最后一页。

调试滑杆不是传感器，也不出现在原生 APP 中。产品界面没有合纸、展开按钮。

## 真机折叠感应

已提供 ios/QianZhi.xcodeproj、QianZhiApp.swift 和 RitualViewController.swift。
在 Mac 上使用包含 iOS 27.1 SDK 的 Xcode 打开项目，选择自己的 Signing Team，修改示例 Bundle Identifier，选择 iPhone Duo 或对应模拟器运行。
项目已以文件夹资源形式引用 ../dist；请保持 ios 与 dist 的相邻目录关系。
无第三方依赖。当前 Windows 环境不能运行 Xcode，Swift 代码尚未编译或完成真机验证，也未签名生成 IPA。

接入方式：
- UIKit UIHingeInteraction 读取系统提供的 closed / partiallyOpen / fullyOpen / unknown。
- 将状态传入 WKWebView 的 QianNative.receive；没有用窗口宽度、旋转角度或网页 Device Posture 代替完全闭合检测。
- 只有 closed 才封签，只有 fullyOpen 才揭晓；partial 不触发。
- 未摇完就展开，会返回原问题，保留文字并重新开始摇签计数。
- 签文已成后再合拢，只收起已有签文；再次展开不会重抽。
- UIKit motionEnded(.motionShake) 驱动真实摇签。闭合时退出键盘并使控制器接收摇动事件。
- 原生模式使用真实视图尺寸、safeAreaLayoutGuide 与 reservedRegions(.occlusion) 避让系统区域，不使用预览框固定尺寸。
- 保存签文时，原生容器打开系统分享面板；网页下载 TXT。

## 画面修正

外屏按 Apple 官方图示，采用铰链侧近直角、外侧大圆角的非对称 D 形。
外屏矩形像素边界为 1398 × 2034、460 ppi；内屏横向边界为 2670 × 1878、430 ppi。
分辨率和 ppi 用于预览比例。官方文字规格未给出此处可直接使用的精确圆角数值，预览圆角按官方图片近似；真实屏幕裁切交给系统。
不绘制时间、信号、电量、系统底部指示条。
问题、签名、诗句和签意均为横排；印章保留少量竖排装饰。

## 整屏签纸视觉更新

APP 的整个可用画面视为连续纸面：纸纤维、淡光和墨痕覆盖整个屏幕，不再绘制屏内纸卡、卡片边框或悬浮阴影。
展签采用整页居中纵向阅读顺序：签号 → 签名 → 两行横排诗句 → 落款印章；不再按左右半屏分栏。
最后的签意页同样采用连续纸面和单栏阅读。中间只保留极淡的纸折痕，不作为布局分隔线。
桌面设备预览轮廓与原生铰链接入保持原有行为。

## 手写优先与水墨视觉

默认使用手写画布，可用触控笔、手指或鼠标直接书写。笔迹按速度、触控笔压力模拟粗细与墨色，带淡墨晕边和细小枯笔纹理。
下方提供“撤回一笔”“清空”；右下角小字“键盘输入”切换为文本框，“返回手写”切回原笔迹。两种模式各自保留草稿，求签使用当前模式的内容。
手写是原笔迹输入，不进行 OCR，也不自动转换为文本；无需联网。签意页展示当次手写原迹。
网页收藏手写签时下载包含笔迹的 HTML 留念页；键盘输入仍下载 TXT。原生分享发送签文及笔迹图片。浏览器本地最多保留最近 10 次收藏，受浏览器存储容量限制。
重启求签清空两种草稿，恢复手写优先，不自动打开键盘。
宣纸使用本地 paper-fibers.svg 叠加纸浆颗粒、纤维和暖色底纹；字体优先系统楷体（不同设备字体可略有差异），主要文字继续横排。
新增检查通过：缩放画布坐标映射、手写封签、撤回/清空、输入模式切换与草稿保留、原迹回看和收藏、重新开始恢复默认手写。画布绘制使用模拟上下文验证逻辑，未完成实际触屏手感及截图验证。

## 更强宣纸与启动分流

新增 expressive.css：更高对比度的纸浆起伏、密集长纤维、粗细纸屑和边缘纸色，整体覆盖整张纸面。
书法改为随包附带的 Ma Shan Zheng 毛笔字体，来源为 Google Fonts 官方仓库 https://github.com/google/fonts/tree/main/ofl/mashanzheng 。许可随附 dist/fonts/OFL.txt；本地加载，无需字体 CDN。标题与签文加入轻微枯墨滤镜，正文保持易读。
首次打开原生 APP 时，先等待 UIHingeInteraction 初始回调，不以窗口宽度猜测屏幕：
- closed：显示独立外屏引导“展开这一念”，没有摇签操作，不会抽签。
- fullyOpen：直接进入内屏默认手写页。
- partiallyOpen：提示完全展开，待 fullyOpen 后进入写愿。
- 尚未收到可用状态：显示等待感应页面，不短暂展示写愿内容。
未填写问题时再次合拢，也回到外屏引导；已有问题的正常封签和摇签流程保持原有行为。
桌面调试区新增“外屏启动 / 内屏启动”用于清空本次草稿并模拟首次打开。调试按钮仅网页可见，不属于真实 APP 的界面。
新增检查通过：内/外屏冷启动、半展开启动、初始状态等待、无问题外屏不抽签、桌面启动预览、字体文件有效性和许可证。原生编译与真机验证仍需 Mac/Xcode 和设备完成。

## 合掌前后轻摇与低重复抽签

封签后的外屏加入 SVG 水墨双手合十夹住手机示意，循环演示前后轻摇三次。实际完成次数独立显示为 0 / 3 至 3 / 3，不由动画自动增加。三次完成后收起动作引导，等待展开。
界面文案说明：手机稳稳轻夹掌心，轻轻前后摇动，回到原位算一次，不需要用力。系统启用减少动态效果时保留静态示意。

动作识别：
- 原生容器改用 Core Motion userAcceleration.z，在完全闭合时以 50 Hz 采样。
- 网页授权后的 devicemotion 使用去重力的 z 轴加速度。
- 三个交替加速度峰与回稳过程构成一个检测周期，含最短时长、超时和冷却，避免单向推移或快速抖动直接累计。
- 这些是加速度模式识别，不能精确测量位移；阈值仍需结合真实握持、机型与使用者节奏校准。当前 Windows 无法完成 Swift 编译和真机校验。
- 桌面调试保留“轻摇一次”。

降低重复：
- 原创签库从 8 支扩充到 48 支，签名、诗句、签意均不同，内容包含决策、沟通、协作、计划、等待、休息等。
- 使用随机洗牌的签袋，一轮内每支只出现一次，48 支用完后再开新一轮。
- 跨轮优先避开最近 8 支，避免轮换边界又见旧签。
- 已抽进度与最近记录独立于收藏，保存在 qianzhi-draw-deck-v1；刷新、重新打开不会主动清空。
- 清除浏览器数据、换设备或存储不可用时，跨重启记录无法保留。存储不可用时当前会话仍维持一轮内不重复。多标签页同时抽签尚未做跨页锁定。
- 签文仍为文学性的随机内容，不根据手写或键盘问题进行 AI 推断。

新增验证通过：3 轮共 144 次抽取的轮内唯一性、随机中途重载、最近 8 支回避、损坏/不可用存储、合掌计数进度、三个模拟前后来回、单向推移与快速抖动排除。
